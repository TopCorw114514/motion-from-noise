# 从噪声中还原运动

基于卡尔曼滤波的传感器数据处理与运动参数估计

> 一句话介绍：位置传感器只能读到“带噪声”的数据，本作品用一套从零写出的卡尔曼滤波算法，把噪声去掉，并进一步还原出物体真实的**位置、速度、加速度**。

---

## 创作背景

本项目是深圳大学物光创新实验室 2026 年招新的作品实践。

最初我也尝试过基于摄像头的“手势控制”“人脸特效”等项目，过程中反复遇到环境配置、模型文件路径、识别准确率等问题。后来我意识到：与其在演示时赌摄像头和环境的稳定性，不如把已经踩过的坑沉淀成更本质的东西——**智能感知的核心，是如何从带噪声的数据里还原真实物理状态**。于是方向改为纯数学/数据处理，重新完成了这个作品。

> 选题取舍：摄像头类项目演示效果好，但依赖硬件、光照和运行环境，评审时不可控因素多；本作品纯软件、可复现，把“从噪声中估计状态”这一智能感知的底层能力讲清楚，也更适合新手在面试中完整解释。

## 一、这个作品解决了什么问题

真实世界中，传感器读数永远不会完全准确。以一台测量小车位置的光电或超声传感器为例：

- 我们真正想知道的是：小车现在在哪、速度是多少、加速度是多少；
- 传感器只能告诉我们一个**近似位置**，读数里混着随机噪声；
- 如果直接把噪声数据拿去用，运动参数的估计就会偏得很厉害。

本项目演示一个完整的“智能感知”处理链路：

1. 模拟一个做匀加速直线运动的物体；
2. 给它加上高斯测量噪声，模拟真实的传感器输出；
3. 用**卡尔曼滤波**在线还原位置、速度和加速度；
4. 与简单的**因果滑动平均**做对比（两者都只能用历史数据），展示卡尔曼滤波“既去噪、又不明显滞后”的优势；
5. 用最小二乘法从处理后的轨迹中**反推出运动参数**（初始位置、初速度、加速度）；
6. 自动生成对比图和实验报告。

## 三、如何运行

1. 打开终端，进入本项目目录；
2. 安装依赖（只需两个常用库）：

```bash
pip install -r requirements.txt
```

3. 运行：

```bash
python run_demo.py
```

程序会自动完成全部计算，并把对比图、CSV 数据与实验报告保存到 `output/demo/` 目录。

也可以固定随机种子，让结果可复现：

```bash
python run_demo.py --seed 42
```

### 3.1 处理你自己的传感器数据（CSV）

把 Excel 里的数据导出成 CSV，满足下面格式：

```text
time,position
0.00,1.024
0.02,0.929
...
```

第一列时间（秒），第二列位置（米）。如果第三列有真实值，程序还会自动做误差对照。

```bash
python process_csv.py --input 你的数据.csv
```

程序会自动估计测量噪声、完成滤波、生成对比图，并把处理后的位置/速度/加速度保存成新的 CSV。

如果暂时没有真实数据，可以先生成一份示例数据体验完整流程：

```bash
python process_csv.py --generate-sample samples/example_sensor_data.csv
python process_csv.py --input samples/example_sensor_data.csv
```

### 3.2 多噪声实验（稳定性测试）

```bash
python run_sweep.py
```

程序会依次在 0.02、0.05、0.08、0.12、0.2、0.35 米六档噪声下运行实验，并生成一张“误差随噪声变化”的汇总图，用来回答“算法是否只在一种情况下有效”。

## 四、数学原理（简化版）

### 1. 运动模型

真实物体做匀加速直线运动：

```text
x(t) = x0 + v0·t + ½·a·t²
```

卡尔曼滤波不直接拟合整条曲线，而是把它看成一段一段推进的状态：

```text
状态向量 = [位置, 速度, 加速度]
```

每隔一小段时间 `dt`，用当前状态预测下一个状态：

```text
位置_new = 位置 + 速度·dt + ½·加速度·dt²
速度_new = 速度 + 加速度·dt
加速度_new = 加速度
```

### 2. 卡尔曼滤波的两步

卡尔曼滤波每一拍都做两件事：

1. **预测**：根据运动模型推算物体现在大概在哪；
2. **更新**：把“模型预测”和“传感器读数”按可信度加权合并。

这里的权重叫**卡尔曼增益 K**：传感器越可信（噪声小），越相信读数；模型越可信，越相信预测。这就是为什么卡尔曼比简单的“滑动平均”更聪明——它不会为了消除噪声而让输出严重滞后。

### 3. 参数辨识

滤波得到干净的轨迹后，用二次多项式最小二乘拟合：

```text
x(t) = p2·t² + p1·t + p0
```

再由系数换算物理量：

```text
初始位置 x0 = p0
初速度  v0 = p1
加速度  a  = 2·p2
```

## 五、实验结果怎么看

运行后你会得到一张对比图，包含：

- 原始含噪数据（红点）与真实轨迹（黑线）；
- 卡尔曼滤波输出（绿线），应明显贴近真实轨迹；
- 移动平均输出（蓝线），作为对照；
- 速度与加速度的估计曲线。

终端还会打印一组量化指标：原始数据的均方根误差（RMSE）、滤波后的 RMSE，以及真实/拟合出的运动参数。误差降得越多、参数越接近真值，说明算法越有效。

运行 `python run_sweep.py` 还会得到一组稳定性数据：当传感器噪声从 0.02 米增大到 0.35 米（相差 17 倍）时，卡尔曼滤波始终能把位置误差降低约 **74%–80%**，说明效果不是“调参调出来的偶然结果”。

## 六、我在这个过程中解决过的问题

1. **环境问题**：早期视觉项目反复遇到 Python 环境不对应、模型文件读不到、中文路径导致乱码。后来统一改为纯软件项目，并把依赖收敛到两个常用库，避免把精力耗在环境上。
2. **对比算法不公平**：滑动平均若使用“未来的数据”会显得很准，但这不符合实时传感器的使用场景。最终我把对比对象改成**因果滑动平均**，让两种算法在同等条件下比较。
3. **数值结果被预热期污染**：滤波器启动前两秒需要收敛，如果拿整段数据算误差会夸大误差。因此在报告中区分了“预热期”和“稳定评估区间”。

## 七、当前不足与未来扩展

本作品目前处理的是**仿真数据**，好处是结果稳定、可以反复演示；下一步可以做三件事让它“接上真实世界”：

1. **接真实传感器**：项目已支持 CSV 导入，下一步可以直接把超声波测距、光电门或手机传感器导出的数据喂进来；
2. **多传感器融合**：位置传感器 + 速度传感器同时输入，扩展测量矩阵 H，展示“1+1>2”的融合效果；
3. **移植到嵌入式**：把核心滤波代码烧进单片机，配合 MPU6050 做姿态解算。

这也正是“智能感知工程”专业的核心方向：从有噪声的数据中还原真实物理状态。
