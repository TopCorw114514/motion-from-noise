# 答辩与演示准备

## 一、30 秒电梯介绍（背熟）

> “我做的是一个传感器数据处理作品。真实传感器读数总带着噪声，比如测位置不准，直接拿去用会算错速度和加速度。我的作品用卡尔曼滤波，在每个采样时刻把物理模型的预测和传感器读数按可信度加权，实时把噪声去掉，还能还原出传感器没有直接测到的速度和加速度。最终程序会输出对比图：原始噪声数据误差很大，滤波之后误差明显下降，并自动反推出运动参数。”

## 二、面试最可能问的问题

### 1. 为什么选择这个方向？

可以这样说：

- 我的专业是智能感知工程，核心能力就是从传感器数据里提取真实信息；
- 我先试过摄像头视觉项目，发现它依赖硬件和环境，效果不稳定；
- 卡尔曼滤波是智能感知的底层通用算法，纯软件就能完整展示数学与工程结合，而且以后可以扩展到真实传感器；
- 这个作品能让我把“为什么需要它、原理是什么、怎么验证效果”完整讲清楚。

### 2. 卡尔曼滤波的直觉是什么？

可以这样说：

- 卡尔曼滤波每一拍做两件事：**先按运动模型猜**（预测），**再拿传感器读数修正**（更新）；
- 关键在“修正多少”由卡尔曼增益决定；
- 传感器噪声小，就多信传感器；传感器噪声大，就多信模型；
- 所以它既能去掉随机噪声，又不会像简单平均那样明显滞后。

### 3. 为什么不用“多求几次平均”？

可以这样说：

- 滑动平均把过去的点一视同仁地平均，为了去噪必须用很长的窗口，窗口越长越滞后；
- 卡尔曼滤波有运动模型，知道物体正在加速，因此能预测下一步大概在哪，再结合读数微调；
- 实验里同样只用历史数据，卡尔曼的位置误差明显小于滑动平均。

### 4. 你的作品用的是仿真数据，不是真实传感器，算不算“做出来”了？

可以这样说：

- 仿真的意义是先在没有硬件干扰的条件下，把算法和评价方法验证完整；
- 真实传感器要解决的“随机噪声”问题，在仿真里已经被建模；
- 代码保留了标准的数据接口，下一步只需把模拟数据替换成超声波、光电门或 IMU 的 CSV，算法无需改动；
- 这符合“先验证核心算法，再上真实硬件”的工程流程。

### 5. 你最想展示的一个数字是什么？

示例答案：

> 在 0.08 米噪声下，原始读数误差约 0.083 米，卡尔曼滤波后约 0.019 米，误差降低 77%；运动参数辨识也能把初速度和加速度反推回真值附近。

需要如实说明：白噪声下“直接对整段原始数据做最小二乘”本身就已经接近无偏，所以我不把“滤波后拟合更准”当作卖点。真正体现滤波价值的，是它能实时逐点输出平滑的位置，以及传感器测不到的速度和加速度。

（具体数值以你电脑上最后一次运行为准。）

补充：我还做了稳定性测试，把噪声从 0.02 米加到 0.35 米，误差降低始终保持在 74%–80%，说明这不是碰巧调出来的效果。

### 6. 你支持真实数据吗？

可以这样说：

> 支持。我写了 `process_csv.py`，任何两列的“时间 + 位置”CSV 都可以直接导入；程序会先自动估计测量噪声，再走同一套卡尔曼流程，输出滤波后的位置、速度和加速度。


### 7. 滤波后的拟合一定比原始拟合更准吗？

不一定，而且通常不该这么讲。若测量噪声是白噪声，直接对整段数据做二次最小二乘已经接近无偏估计；先滤波反而会引入时间相关性，可能让离线拟合结果变好或变差。

所以这个项目里：
- “位置 RMSE 下降”证明的是**实时滤波去噪有效**；
- “参数辨识”展示的是**能从轨迹反推物理量**；
- 两者是不同的事，报告中同时列出原始拟合和滤波后拟合，就是方便评委看到真实情况。

如果被追问，可以说：“滤波的价值不在离线拟合精度，而在实时性——每个采样时刻都能给出平滑的位置，以及传感器没有直接测到的速度和加速度。”

## 三、演示视频脚本（约 2 分钟）

1. **0–15 秒 开场**：介绍“为什么传感器数据不能直接用”，展示一条抖动的红色噪声曲线。
2. **15–35 秒 展示代码结构**：指出核心文件 `kalman_filter.py`，说明状态是位置/速度/加速度，算法是预测+更新两步。
3. **35–70 秒 运行**：运行 `python run_demo.py`，指着黑线（真实）、绿线（卡尔曼）、蓝线（滑动平均），说明卡尔曼更贴近真实且没有明显滞后。
4. **70–90 秒 参数辨识**：展示真实参数、原始拟合和滤波后拟合三列，说明参数辨识功能本身可用，并如实解释“离线拟合不是滤波的卖点”；接着强调滤波的真正价值是逐点实时输出速度与加速度。
5. **90–105 秒 稳定性**：切到 `run_sweep.py` 的结果图，展示噪声增大 17 倍后误差仍降低 74%–80%。
6. **105–120 秒 结尾**：说明下一步（接真实传感器 CSV、多传感器融合、嵌入式姿态解算）。

视频里不需要念代码，重点是**让评委看懂“噪声 → 滤波 → 参数”这条主线**。
